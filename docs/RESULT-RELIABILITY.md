# 任务结果可靠性与恢复

本说明适用于包含本次修复的控制面和 Agent 源码，不能据此认定已有安装包包含修复。控制面与 Agent 必须配套升级，企业交付还需要固定对应社区提交并完成正式发布验收。

## 完成与交付

每次任务执行创建独立的 `gpuflow-result-<job-id>-<随机值>/` 目录，包含：

- `artifacts/`：容器写入 `$GPUFLOW_ARTIFACT_DIR` 的原始文件。
- `training.log`：完整 stdout/stderr；运行中页面仍展示最近 64 KiB。
- `gpuflow-archive-<随机值>/artifacts.tar.gz`：本次执行独有的归档。
- `recovery.json`：任务 ID、执行次数、节点、更新时间和交付状态；不保存认证 Token。

成功要求程序成功退出、完整日志及非空产物上传被确认、控制面确认本次执行的成功状态。仅在上传和本次终态均确认后清理工作目录；计算失败但结果交付完整且失败终态已确认时，也可清理。终态未确认、任务被取消或已被新执行取代时保留本地结果。计算失败时沿用原有计算重试预算，但上传失败不会自动重跑已经完成的计算。

产物打包、日志落盘或上传失败会明确使任务失败，并保留本地结果及恢复信息。Agent 发送 `retryable: false`，使该类失败不消耗计算重试预算重新训练。取消任务也保留已产生的日志和文件；取消不会等候长时间上传。

## 上传中断

网络错误、HTTP 408/429/5xx 会在同一 session/attempt 内退避重试，等待由 250 ms 增长到最多 8 s。每次从同一本地文件开头重新传输，不重新计算，也不声称支持跨连接按字节偏移续传。服务器只发布完整上传并再次确认执行身份后的对象，半截数据不对外可见。

每个文件默认最多重试 30 分钟（包括传输时间），可通过 Agent 的 `-artifact-upload-timeout 2h` 调整。应根据实际文件大小和网络吞吐设置窗口。身份失效、请求非法或容量超限等错误不会无限重试。上传超时后，任务显示结果交付失败、本地保留位置可在任务输出和 Agent 日志中查到。

大文件协议、1 TiB 单文件边界及代理配置见 [ARTIFACT-UPLOADS.md](ARTIFACT-UPLOADS.md)。任务 CPU/内存预留和 Docker 限制见 [HOST-RESOURCES.md](HOST-RESOURCES.md)。

## 回收保留的结果

生产节点应将 `GPUFLOW_ARTIFACT_WORKDIR` 设置为容量足够的持久目录；容器 Agent 要将该目录以相同绝对路径挂载。未配置时使用操作系统临时目录，不应依赖该目录抵抗系统清理。保留目录不会自动过期，需要管理员监测磁盘使用并在回收后清理。

1. 从任务输出或 Agent 日志找到 `results retained on node ... at ...`，核对目录内 `recovery.json` 的任务 ID、执行次数和节点。
2. 如果 Agent 仍在上传窗口内，先恢复对象存储/网络并等候自动重试；不要移动或修改正在上传的文件。
3. 上传窗口已经结束、任务已取消或 Agent 已重启时，复制完整目录至受控存储。即使打包失败，`artifacts/` 仍包含原始结果；可以直接回收这些文件，不必重跑训练。复制后核对文件数量、大小及摘要，再清理源目录。
4. 已失效 session/attempt 的结果不会自动覆盖新执行的产物。Agent 重启后的任务接管仍遵循原有清理和重试机制；此版本不提供跨进程自动续传或将失败任务重新标成成功的接口。需要重新计算时，用户显式重跑任务。

保留目录保护的是已落盘文件，不代表训练程序已实现检查点保存，也不保证突然断电时应用尚未写出的数据可以恢复。

## 验证

回归覆盖多任务并发归档与交付、上传连接中断后完整重传、上传窗口耗尽后的文件保留和非重试失败、取消/旧执行隔离、最终确认丢失以及完整日志保存。大文件 API 测试以生成流越过旧 1 GiB 边界，不把整个文件装入内存。真实 Docker/S3 验证采用独立测试服务，不连接客户实例。
