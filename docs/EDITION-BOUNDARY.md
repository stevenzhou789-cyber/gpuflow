# Community 与 Enterprise 版本边界

本文件约束官方发行版、默认 API、页面和交付产物。共享内核允许公开，开发者可以基于公开接口和实现自行研发。Community 按裁剪版小步维护，保留可实际使用的批任务闭环；Enterprise 在私有仓库组合完整的企业治理、运营和交付能力。

## 代码归属与产品行为

| 范围 | 公开共享代码 | 官方 Community | Enterprise 私有组合 |
| --- | --- | --- | --- |
| 任务闭环 | 节点注册、资源匹配、排队、执行、日志、产物、重试、MySQL/MinIO 持久化 | 保留；单一 `default` 项目、FIFO、整节点独占 | 复用并叠加企业治理 |
| GPU 与节点机制 | 逐卡数据模型、分配算法、设备探测、健康状态机、维护排空机制可以共享 | 展示型号、数量和显存等基础资源，保留基础健康状态与异常停止/恢复；默认关闭逐卡详情及 Agent 周期设备复检，不提供维护管理操作 | 私有管理 API、完整界面、角色权限及操作审计 |
| 项目与调度 | 项目模型、配额判断、公平调度、调度解释、决策持久化及其测试可以共享 | 不开放项目管理、项目 Token、公平调度和调度解释产品入口 | 私有项目 Token、管理 API、授权、审计及管理界面 |
| 使用量 | 原始执行记录及其兼容字段可以共享 | 不提供企业用量账本、成本洞察和报表 | 独立历史账本、项目/设备汇总、区间报表和 CSV 导出已在私有仓库 |
| 商业治理 | 能力描述符、扩展接口和请求作用域类型可以共享 | 不提供企业角色、审计服务、License 签发/验签或自动 Registry 分发服务 | 私有 RBAC、项目认证、HTTP 审计、License 验签、自动镜像分发 |
| 页面与交付 | 基础任务页面、通用组件、社区构建和部署 | 发布社区界面和社区产物 | 企业完整界面 overlay、产品入口、签名安装升级与正式交付在私有仓库 |

公开源码中存在企业能力名称、兼容字段、通用接口或共享算法，不等于官方 Community 已开放对应产品。修改公开源码自行开发与取得官方 Enterprise 产品是两件不同的事；能力开关用于产品组合，不能用于承诺公开算法保密。

## 官方 Community 契约

- `edition.Community()` 只启用 `basic_scheduler`。所有已知企业能力必须明确为 `false`；新增或未知能力不得未经产品边界审查就默认启用。
- `/v1/capabilities` 返回与实际 API、Agent 和页面一致的社区描述符。企业专属功能不能仅通过隐藏菜单、前端变量或请求参数开启。
- `/enterprise/v1` 及其子路径对所有 HTTP 方法明确返回 JSON `404`，不能由单页应用回退返回 `200` HTML；社区不注册企业管理路由。
- `per_gpu_inventory=false` 时，节点注册和健康更新请求中的非空 `devices`、`driver_version`、`docker_version` 返回 `400`；注册、清理完成、节点列表（含分页）及健康更新响应均不输出这些逐卡/环境明细，投影不得修改 Store 持久状态。基本健康状态、容量更新和 `DEGRADED` 停止/恢复继续可用。
- 调度解释能力关闭时，对应 HTTP 入口返回 `404`。基础节点查询和任务执行协议继续正常工作。
- 注册、心跳、会话校验、离线处理、取消收尾、cleanup ack 和安全恢复属于可靠性基础能力。关闭企业设备健康治理不能删除这些机制。
- 社区页面不包含可直接操作的企业管理、角色/项目 Token、License、账本报表或审计控制台。必要的版本说明、升级链接与通用展示组件可以保留。

## 数据和升级约束

产品裁剪以入口和输出投影为边界，不删除既有数据库列、JSON 兼容字段、迁移、任务记录或持久化决策结构。读到旧版或企业产生的数据时，隐藏未开放的信息不得改写或清空原始数据。

上述保证仅针对 HTTP 读取与响应投影。正常节点注册和健康更新继续遵循既有持久化语义，`HEALTHY` 更新仍会以请求中的完整库存替换旧快照；不能由响应裁剪推断企业切换到社区后的写操作会保留所有企业明细，也不能据此认定支持 Enterprise → Community 跨版降级。

这项保证针对读取投影。注册和健康更新仍按原有规则更新持久化库存；未上报的明细可能被替换，不能据此承诺 Enterprise 数据库可直接降级给 Community 使用，也不能保留与新容量不一致的旧设备快照。

任务分配、GPU 预留、项目配额、调度公平进度和决策持久化继续保持原有事务与锁的一致性。节点维护排空与分配保持同锁语义；cleanup ack 确认前不得释放仍可能运行的任务资源。版本回退必须遵循对应版本的兼容与备份说明，不能由“页面已裁剪”推断支持数据库降级。

## 可执行检查与验收用例

每次涉及版本边界的变更至少覆盖以下检查；实现仍在迁移中的条目应在变更说明中明确列为未完成，不能只更新文档就宣称通过。

| 检查 | 预期 |
| --- | --- |
| `go test ./pkg/edition` | 验证完整社区能力声明；只有基础调度启用，任何其他能力启用均失败 |
| 社区 API 边界测试 | 企业命名空间和关闭的解释入口为 JSON `404`；逐卡/环境明细写入为 `400`，基础健康状态更新仍可用 |
| 社区基础行为测试 | FIFO、整节点独占、默认项目、任务日志与产物、Agent 会话及清理恢复仍有效 |
| 社区输出与兼容测试 | 节点详情不暴露已关闭的产品投影；读取兼容数据不改变持久化原值 |
| 前端构建与页面检查 | 企业操作界面未进入社区页面及构建包；基础页面可正常使用 |
| 企业配套回归 | 固定 Community 提交后，企业私有入口、权限、账本、维护及 overlay 能组合运行 |
| 仓库与产物检查 | 公共跟踪文件、构建上下文、压缩包、前端包与镜像不混入私有产品代码或本地敏感文件 |

仓库和产物检查应针对私有模块来源、路径、内容及构建清单，不以 `enterprise` 字符串、公开 feature 常量或共享内核测试名称一刀切。私有产品入口、RBAC、License 验签、项目 Token、HTTP 审计、独立账本/报表、Registry publisher 和企业 overlay 不得从本地临时副本进入公共提交或社区包。

`.gitignore` 只防普通误暂存，不能移除已跟踪文件或阻止强制添加；`.dockerignore` 只控制对应构建上下文。两者必须配合跟踪文件检查、构建输入清单和实际产物核验。企业目录、工作副本、归档、密钥、客户 License、`.env`、数据、备份和缓存不能因位于社区工作区就自动纳入提交或打包。

社区和企业分别保留各自 GitHub/GitLab CI 与正式发布门禁。两端推送成功不代表两端 CI 成功；版本标签、正式签名及发布批准按现有流程管理。

## 本地复验命令

在社区仓库根目录执行：

```text
go test ./...
go vet ./...
node --test scripts/check-community-boundary.test.mjs
node scripts/check-community-boundary.mjs
npm --prefix web run build
```

默认边界检查只扫描 Git 跟踪的候选文件；新增文件应在纳入候选清单后再次检查。CI 同时对 Docker 实际复制的源码树、重新构建的内嵌前端和打包前部署目录执行 `--source-tree` / `--delivery-tree` 检查。不要对含本地工作副本与缓存的整个开发目录使用这两个目录模式；它们面向受控构建或交付目录。

安装 Python 并启动 Docker 后，可验证默认、named 和 GitLab 专用上下文的真实排除规则：

```text
python scripts/test-build-context.py
```

该检查仅向临时目录写入合成文件，使用 `FROM scratch` 导出上下文；不使用真实密钥、客户数据、任务容器或远端发布。需要同时检查相邻企业仓库时增加 `--enterprise-root ../gpuflow-commercial`。
