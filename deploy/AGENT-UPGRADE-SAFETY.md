# Community Agent 升级交接

社区继续只有基础调度能力。`agent-handoff` 是容器内 root 可访问的本地
Unix socket 交接，不注册维护 API，不新增维护页面、能力开关或企业授权功能。

批量升级先校验目标镜像，再暂停旧进程领取任务，等待已领取任务完成执行、
日志上传及终态确认；排空期间心跳和会话租约继续有效。确认无任务容器后才
停止旧进程，并等待旧会话过期。新进程必须完成注册、启动清理、首次心跳及
GPU 探测；镜像也必须等于准备阶段捕获的不可变本地 ID，才报告升级成功。
控制面已经分配但旧 Agent 尚未领取的任务沿用现有会话接管逻辑，不增加重试。

这项就绪检查不代表真实 GPU 作业验收。升级后仍需在指定验收节点提交实际
任务，核对执行、日志和资源释放。若替换失败，回退也必须验证旧镜像和会话
就绪；无法安全排空替换进程时停止操作并保留旧环境备份，不能强杀任务后
宣称回退成功。

旧版 Agent 没有本地交接命令，批量脚本会明确拒绝。首次迁移需要预先安排
停机窗口：停止提交任务，等待控制面没有 assigned/running/canceling 任务，
同时核对节点没有 GPUFlow 任务容器；停止旧 Agent 后再次核对控制面任务状态，
发现新增分配时先恢复旧 Agent 并排空。保持提交入口关闭，完成镜像替换、
会话接管及真实任务验证后再恢复提交。不能把旧版“不支持交接”当作可跳过的
检查，也不能用社区版不存在的节点维护 API 实现迁移。

节点 ID 统一为 1–64 个 ASCII 字母、数字、点、下划线或连字符，并以字母或
数字开头。非法 ID 在注册前拒绝；已有非法 ID 的节点需在停机窗口改为合法 ID
后重新注册，不能自动重命名带有活动任务的节点。
